# Contributing

Thanks for helping improve this template. This guide gets you from clone to pull request.

## Quick path

1. Generate the JWT signing keys: `make keys`
2. Run the API: `make run` (listens on `0.0.0.0:8080`)
3. Before opening a pull request: `make check lint test`

## Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Go | the `go` directive in [`go.mod`](go.mod) | required |
| make | any | required |
| openssl | any | required by `make keys` |
| golangci-lint | v2.15.0 | optional; `make lint` falls back to `go run` (needs network) |
| swag | v1.16.4 | only to regenerate the OpenAPI docs |
| Docker | any | only for `make docker-build` |

## Workflow

- **Branches:** `<type>/<short-description>`, for example `feat/user-endpoint` or `fix/token-expiry`.
- **Commits:** [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `build:`, `ci:`, `chore:`). The release changelog is generated from them.
- **Tests:** keep tests in the same commit as the behavior they cover.
- **Checks:** run `make check lint test` before pushing. CI runs the same checks plus `govulncheck`, a swagger drift check, the init script test and a Docker build.
- **Release config:** when you change `.goreleaser.yaml`, run `make release-check` (it falls back to `go run`, which needs network).
- **Bootstrap script:** when you change `scripts/init.sh` or `scripts/init_test.sh`, run `make test-init` (CI runs it too).
- **Pull requests:** fill in the template and link the related issue.

## Adding an endpoint

The step-by-step guide (handler, route, model, tests, swagger annotations) lives in [`AGENTS.md`](AGENTS.md). Follow it so the layout stays consistent.

## Regenerating the OpenAPI docs

The `docs/` package is generated by [swag](https://github.com/swaggo/swag). After changing handler annotations:

```bash
go install github.com/swaggo/swag/cmd/swag@v1.16.4
make swagger
```

Commit the regenerated `docs/` together with the handler change. CI fails if `docs/` is out of date.

## Security

Never commit keys, tokens or credentials (`keys/` is gitignored). Report vulnerabilities privately as described in [`SECURITY.md`](SECURITY.md).
